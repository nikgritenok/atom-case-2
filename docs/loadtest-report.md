# Отчёт о нагрузочном тестировании

Стенд: `docker compose up --build` с `RATE_LIMIT_MAX=5000` (базовый лимит 100/мин оставлен для защиты, для нагрузки поднят). Команда: `BASE_URL=https://localhost ADMIN_EMAIL=admin@test.ru ADMIN_PASSWORD=password123 npm run load`.

Сценарий `k6/load.js`: рампа 5 VUs 30с, плато 20 VUs 60с, спад 30с. Только чтение: список оборудования, список заявок, отчёт нагрузки. `insecureSkipTLSVerify` из-за snakeoil-серта.

## Итог

| Метрика                 | Значение          | Порог   | Статус  |
| ----------------------- | ----------------- | ------- | ------- |
| `http_req_failed`       | 0,00% (0 из 3271) | <1%     | зелёный |
| `http_req_duration p95` | ~15 мс            | <800 мс | зелёный |
| RPS средний             | ~27               | —       | —       |
| Итерации                | 1090 за 2 мин     | —       | —       |

Первый прогон при лимите 100/мин дал 77% 429 — лимитер в памяти режет нагрузку штатно. После поднятия лимита ошибок нет.

## Поведение по дашборду Grafana

Во время прогона панель RPS показывает рост до ~27 запросов/с, p95 latency держится в десятках миллисекунд, доля 5xx нулевая. Кэш nginx на `/api/reports/` даёт HIT при повторных запросах с тем же токеном. База и приложение без деградации.

## Пределы

Один инстанс приложения, лимитер в памяти (не shared store), snakeoil TLS. Для роста RPS: горизонтальное масштабирование app за nginx upstream и внешний сторедж лимита.
